# Настройка и оценка локальной E5

## Цель и оборудование

Настроить локальную модель embeddings `intfloat/multilingual-e5-base` для русского химического текста и измерить её CPU/RAM-нагрузку без отправки учебника внешнему embedding API.

Целевая машина, на которой выполняется настройка:

- Intel Core i7-8550U, 4 физических ядра / 8 логических;
- 8 ГБ оперативной памяти;
- около 129 ГБ свободного места на диске C: (на момент проверки);
- видеокарты нет.

Репозиторий пока не содержит приложения. Setup изолирован в `.venv-e5/`; он не меняет зависимости будущего приложения. Benchmark использует небольшие синтетические химические тексты, не читает и не индексирует PDF.

## Конфигурация

- Модель: `intfloat/multilingual-e5-base`, ревизия `d128750597153bb5987e10b1c3493a34e5a4502a`.
- Размер embedding: 768 float32 значений; Qdrant collection — `Cosine`.
- Префикс документа: `passage: `; запроса: `query: `.
- Максимальная длина модели: 512 токенов. До индексации PDF необходимо сегментировать текст так, чтобы префикс также укладывался в предел; не допускать тихого truncation.
- Batch size при старте: 1. После замеров можно вручную сравнить 2 и 4, только если остаётся достаточно RAM.
- Веса модели — около 1,1 ГБ. Первый запуск скачивает их с Hugging Face и требует интернет; последующие запуски используют локальный кэш. Тексты для embedding обрабатываются локально.

## Установка на Windows

Нужен Python 3.12 x64. Команды выполнять из корня проекта в PowerShell:

```powershell
py -3.12 -m venv .venv-e5
.\.venv-e5\Scripts\python.exe -m pip install --upgrade pip
.\.venv-e5\Scripts\python.exe -m pip install -r requirements-e5.txt
.\.venv-e5\Scripts\python.exe scripts\benchmark_e5.py
```

При первом запуске benchmark загрузит веса модели в стандартный кэш Hugging Face пользователя. Запросы модельной карточки и весов идут в Hugging Face, но PDF/тексты проекта в этот шаг не передаются. Не помещать `.venv-e5/` и каталог кэша в Git.

Чтобы сравнить размер batch на коротких синтетических строках:

```powershell
.\.venv-e5\Scripts\python.exe scripts\benchmark_e5.py --batch-size 1
.\.venv-e5\Scripts\python.exe scripts\benchmark_e5.py --batch-size 2
```

Benchmark печатает время загрузки, время кодирования тестовых passage/query, наблюдавшуюся RSS процесса и форму матрицы cosine similarity. Это smoke-test окружения и инференса, а не тест качества поиска по учебнику. Для оценки качества нужен отдельный размеченный retrieval-набор.

## Первичный замер целевой машины

Первые запуски выполнены на указанном компьютере (i7-8550U, 8 ГБ RAM) с CPU-версией PyTorch и batch size 1:

- весовые файлы модели заняли около 1082 МиБ в кэше Hugging Face;
- первичное скачивание и выполнение заняли около 19 минут; это не оценка времени повторного старта;
- повторный запуск с кэшем: модель загрузилась за 20,4 с; RSS процесса был 380 МиБ до загрузки и 1318 МиБ после загрузки;
- пиковый RSS процесса во время smoke-test: около 1669 МиБ;
- при повторной проверке 4 синтетических passage закодированы за 1,06 с, 3 синтетических query — за 0,39 с;
- модель выдала ожидаемую размерность 768; cosine similarity матрица имела форму 3×4, top result соответствовал всем трём синтетическим вопросам.

Это краткий smoke-test, а не репрезентативный throughput-тест документа и не замер общей памяти системы. Qdrant не запускался; следует отдельно проверить суммарную нагрузку E5 + Qdrant + приложение до массовой индексации. UTF-8 отображение результатов в Windows-консоли включено в скрипте.

## Оценка памяти и практические ограничения

На диске следует оставить не менее 3–5 ГБ для модели, Python/PyTorch и кэша; коллекция для одного учебника обычно занимает существенно меньше, хотя объём текста и Qdrant payload зависит от сегментации.

На машине с 8 ГБ RAM модель может запускаться на CPU, но одновременная работа Windows, PyTorch, приложения и Qdrant может приблизиться к лимиту памяти. Поэтому:

1. начать с batch size 1 и закрыть тяжёлые приложения;
2. сравнить текущую RAM до загрузки, после загрузки модели и после инференса;
3. затем запустить Qdrant и приложение вместе и измерить общий peak working set;
4. если памяти не хватает, не увеличивать batch size; рассмотреть ONNX/OpenVINO или квантованный runtime после отдельного тестирования совместимости и качества;
5. использовать локальные векторы/извлечения без генерации либо подобрать компактную локальную LLM отдельно — память для E5 не включает память LLM.

Значения, измеренные benchmark на целевой машине, нужно записать в план разработки вместе с версией зависимостей. Данные не должны заменяться только теоретической оценкой.
