# Инструкции для агентов

## Проект

- Проект «Репетитор по химии» разрабатывается на русском языке.
- Перед изменениями прочитай [README.md](README.md) и относящиеся к задаче разделы [плана](docs/План-разработки-RAG.md).
- Пользовательские промпты, содержащие требования или решения по проекту, добавляй дословно и с датой в [журнал промптов](docs/Промпты-проекта.md).

## Источники RAG

- Для корпуса RAG используй только `учебники/5eb6e10c5b_himija_8_klass_o_s_gabrieljan_2025_g.pdf`.
- Не индексируй и не используй для ответов остальные PDF из `учебники/`, пока пользователь явно не изменит это требование.
- Онтология проекта находится в `учебники/химия2.ttl`; источник для неё — `учебники/K_Zommer_Akkumulyator_Znany_Po_Khimii.pdf`. Эта книга не входит в корпус RAG. При отдельной задаче на онтологию сохраняй происхождение и проверяемые ссылки на печатные страницы.
- Ответы RAG должны быть на русском языке и по возможности содержать ссылки на страницы учебника. При недостатке подтверждений сообщай об этом, не выдумывай факты или цитаты.

## Модель, harness и векторный поиск

- Используй локальную E5 для embeddings и локальную Qwen2.5 GGUF через llama-cpp-python для генерации. DeepSeek API не используется.
- Для локального запуска выбран Qdrant Community Edition (self-hosted, Apache License 2.0). Qdrant хранит векторы и JSON payload; URI сущностей онтологии можно использовать в payload и фильтрах.
- Qdrant не является RDF/OWL-хранилищем и не выполняет онтологический вывод. Для чтения RDF-графа и обхода отношений используй отдельную RDF-библиотеку/хранилище; сохраняй URI как связь между фрагментами и понятиями.
- Используй `intfloat/multilingual-e5-base` локально: 768 dimensions, cosine, `passage: ` для документов и `query: ` для запросов; соблюдай ограничение 512 токенов и проверяй размерность/схему коллекции Qdrant.
- Гибридный поиск: dense retrieval в Qdrant + BM25 по текстам точек локально, объединение через RRF. Онтологию обрабатывай отдельным RDF-инструментом и связывай найденные понятия с фрагментами через URI/payload; не полагайся только на векторный поиск.
- Retrieval и генерация должны оставаться локальными; не добавляй внешние LLM/API. Для каждого ответа передавай модели не более трёх лучших фрагментов из локальной базы.
- Следуй принятым в проекте harness-процессам и проверкам после того, как они будут определены. Не заявляй о реализованных функциях, пока они не созданы и не проверены.
- При реализации индексации и LLM-orchestration следуй [требованиям к harness](docs/Требования-к-harness.md) и [плану тестирования RAG](docs/План-тестирования-RAG.md); не добавляй передачу фрагментов внешней LLM.
- Для настройки локальной E5 используй [инструкцию](docs/Локальная-E5.md) и запускай [benchmark-скрипт](scripts/benchmark_e5.py) в отдельном окружении; не включай `.venv-e5/` и кэш модели в Git.
- Для индексации и вопросов используй `scripts/local_rag.py`; локальные данные Qdrant и GGUF-модель находятся в игнорируемых Git каталогах `.local-data/` и `.local-models/`.

- Сохраняй существующие пользовательские файлы и не удаляй/не переименовывай учебники без запроса.
- Делай небольшие целевые изменения и обновляй непосредственно связанную документацию.
- Запускай уместные проверки; если инфраструктуры для проверки ещё нет, укажи это явно.
