# Репетитор по химии

Проектируемый русскоязычный сайт с RAG-системой по химии, основанной на учебном источнике и химической онтологии.

## Зафиксированные решения

- **Язык интерфейса и ответов:** русский.
- **Источник для RAG:** только [учебник за 8 класс](учебники/5eb6e10c5b_himija_8_klass_o_s_gabrieljan_2025_g.pdf) — файл уже находится в каталоге `учебники/`.
- **Онтология:** [химия2.ttl](учебники/химия2.ttl), созданная по книге К. Зоммера [«Аккумулятор знаний по химии»](учебники/K_Zommer_Akkumulyator_Znany_Po_Khimii.pdf). Книга Зоммера служит источником для онтологии, но не входит в корпус RAG.
- **Embeddings:** локальная `intfloat/multilingual-e5-base` (768 измерений, префиксы `passage:`/`query:`, метрика `Cosine`).
- **Генерация:** локальная CPU-модель Qwen2.5-1.5B-Instruct в GGUF Q4_K_M; DeepSeek API не используется. Для ответа в контекст LLM передаются не более трёх верхних фрагментов.
- **Запуск:** локальный.
- **Векторное хранилище:** локальный Qdrant Community Edition (бесплатный self-hosted вариант, [Apache License 2.0](https://github.com/qdrant/qdrant/blob/master/LICENSE)).

В каталоге `учебники/` также есть PDF-файлы для других классов. По текущему требованию они **не входят** в корпус RAG и не должны индексироваться.

## Состояние

Онтология проверена по доступным страницам книги-источника и внесены исправления. Проверка не является построчной аттестацией всех аксиом, свойств и экземпляров; ограничения описаны в метаданных онтологии. Исходный PDF Зоммера — скан, поэтому часть сопоставления выполнялась по изображениям страниц и OCR.

Qdrant хранит векторы и JSON payload с метаданными, включая URI понятий онтологии, и поддерживает фильтрацию по payload ([документация Qdrant](https://qdrant.tech/documentation/manage-data/payload/)). Он не выполняет RDF/OWL-вывод: для обхода связей и логики нужно отдельно загружать `учебники/химия2.ttl` в RDF-библиотеку/хранилище. Связь между фрагментом RAG и понятием онтологии хранится как идентификатор/URI в метаданных.

Для embeddings выбрана локальная [intfloat/multilingual-e5-base](https://huggingface.co/intfloat/multilingual-e5-base), поддерживающая русский язык. Её веса нужно загрузить один раз; embedding-запросы затем обрабатываются локально, без отправки учебника внешнему embedding-сервису. Вектор содержит 768 измерений, текст документа должен иметь префикс `passage: `, запрос — `query: `; максимальная длина модели — 512 токенов. Гибридный поиск реализован как dense retrieval в Qdrant + локальный BM25 по payload с объединением через RRF; связи онтологии требуют отдельного RDF-шагa.

Для локальной RAG-системы предусмотрены [зависимости](requirements-local-rag.txt) и [CLI-скрипт индексации/вопросов](scripts/local_rag.py). Qdrant работает в локальном persistent-режиме; dense-поиск Qdrant и BM25 по локальному тексту объединяются через RRF. Пример запуска после настройки окружения и скачивания модели:

```powershell
.\.venv-e5\Scripts\python.exe scripts\local_rag.py index
.\.venv-e5\Scripts\python.exe scripts\local_rag.py ask "Что такое атом?"
```

Установка, загрузка GGUF и проверка системы описаны в [инструкции локального RAG](docs/Локальный-RAG.md). Настройка E5 и её отдельные замеры CPU/RAM описаны в [инструкции E5](docs/Локальная-E5.md). `scripts/benchmark_e5.py` остаётся синтетическим smoke-test и не индексирует PDF.

В конфигурации не предусмотрено обращение к DeepSeek: извлечение текста, E5, локальная Qdrant, BM25 и генерация Qwen выполняются на компьютере. Скачивание программ, весов E5 и GGUF-модели при установке требует Интернета; во время поиска/генерации внешние API не вызываются. Перед генерацией приложение ограничивает prompt тремя фрагментами максимум.

`scripts/local_rag.py` реализует локальную индексацию разрешённого PDF и CLI-вопросы; это ещё не интегрировано в сайт. Для установки и проверки см. [инструкцию локального RAG](docs/Локальный-RAG.md).
